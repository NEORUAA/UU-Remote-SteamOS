## 日常操作の改善

最近の改善は、中国語入力、文字の貼り付け、ウィンドウ操作に重点を置いています。

| 場面 | 使用時の背景 | 以前の体験 | 改善後の体験 |
| --- | --- | --- | --- |
| スマートフォンの中国語 | 以前の Plus スマートフォン入力 | 送信した文字の一部が正しくデスクトップに届かなかった | スマートフォンの直接接続で送信した中国語が Ubuntu に正しく入力される |
| コピーと貼り付け | 以前の Plus テキスト中継 | 新しくコピーしても古い文字が貼り付く場合があった | 新しくコピーした文字が貼り付け用に更新され、通常の PC からの文字コピーが使える |
| UU の設定とポップアップ | 以前の Plus 管理ビュー | 管理画面がデスクトップに重なり、戻った後のフォーカスがずれることがあった | 設定画面をデスクトップ画像と分け、管理ビューを閉じると入力フォーカスがデスクトップに戻る |
| 鮮明さとサイズ | Plus の画面拡大試験 | 試した 4K 画像の拡大は細部を増やさず、かえってぼやけた | 4 種類のサイズで全体を表示し、保存サイズへ復元できる。試した画像では 4K で十分 |
| 再接続 | Mac UU クライアント更新 | Mac UU 更新後に日常操作を確認する必要があった | 更新後も再接続、中国語の直接入力、文字の貼り付けが使え、4K の体感も同程度 |

[比較ページ](upstream-comparison.md)では、上流からの機能、新版への対応、Plus の追加機能、Plus 使用中の修正を分けて説明します。

![上流の基盤、Plus の変更と設計上の見込み](../../images/uu-plus-evolution-en.png)

[編集可能な SVG](../../images/uu-plus-evolution-en.svg)

**設計上の見込み：**テキストを適時更新し、フォーカスを確実に戻すことで、貼り付けのやり直しや設定とデスクトップを行き来する際の中断を減らせます。小さい画面はフレーム当たりの画素数を減らします。見える応答にはキャプチャ、エンコード、ネットワーク、操作端の表示も影響します。

| 画面 | 1フレームの画素 | 1080p比 |
| --- | ---: | ---: |
| 1280 × 720 | 921,600 | 0.44× |
| 1920 × 1080 | 2,073,600 | 1.00× |
| 2560 × 1440 | 3,686,400 | 1.78× |
| 3840 × 2160 | 8,294,400 | 4.00× |

画素面積の比です。元画面全体を捕捉する場合があり、圧縮／動き／回線で負荷が変わります。smart sizing は物理解像度を変更しません。

| 設定 | 役割 |
| --- | --- |
| Ubuntu画面 |中継サイズ、まず1080p、精細文字／領域は4K |
| 画質/FPS/True Color |圧縮／要求更新／対応色 |
| `uu-remote quality bitrate 20` |20 Mbps上限、`0`解除、低すぎると動きの細部減少 |

[画質](quality-guide.md)にメニュー／コマンド／復旧があります。

## ビルドコスト

ソースからの完全ビルド、準備と検証を含む結果：

| 項目 | 結果 |
| --- | --- |
| 時間 |699.851秒、約11分40秒 |
| 制限 |CPU2コア相当、メモリ4 GiB |
| 報告最大 |約1.8 GB、service manager丸め値 |
| swap |0バイト |
| 出力 |Windowsバイナリ13 個 |
| 再現性 |固定入力、異なるsource/outputで同じバイト |

通常入口はパス正規化と明示設定を使用。別マシンではダウンロード／コンパイラーにより時間が変わり、検証済み出力は再利用可能。[ビルド](source-build.md)。

| 環境 | Ubuntu | GNOME | Windows UU |
| --- | --- | --- | --- |
| 上流 |24.04|46|4.33.0.8907|
| Plusローカル |26.04|50|4.42.0.2770|

## 同条件測定

既存記録には、固定した上流と Plus の操作端 FPS、入力から画面応答までの遅延を同条件で比較した測定はありません。中継の計時と CPU 割当の実験は部品単位の測定です。


ホスト／操作端、解像度、アプリ、回線、画質/FPS/bitrateを固定。独立環境と固定版、上流24.04制約を考慮します。入力から画面応答までを計時し、再現可能な動きで操作端更新を数えます。繰返し、ばらつき／文字の明瞭さと方法を記録します。
