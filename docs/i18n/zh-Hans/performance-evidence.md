## 日常使用改善

更新重点落在中文输入、文本粘贴和窗口操作。

| 场景 | 使用背景 | 此前体验 | 改进后的体验 |
| --- | --- | --- | --- |
| 手机中文 | 此前 Plus 手机输入 | 手机提交的部分文本未正确到达桌面 | 手机直连提交的中文能正确输入 Ubuntu 桌面 |
| 复制粘贴 | 此前 Plus 文本中继 | 复制新内容后，粘贴有时仍是旧文字 | 新复制的文本及时更新到桌面粘贴，普通电脑文本复制粘贴正常 |
| UU 设置／弹窗 | 此前 Plus 管理视图 | 管理窗口可能覆盖桌面画面，返回后焦点不对 | 设置窗口与桌面画面分开，双控制端切换导致的焦点丢失仍未解决 |
| 清晰度／画布 | Plus 画布扩展试验 | 4K 源继续放大没有增加细节，反而更模糊 | 四档完整显示桌面，并可恢复已保存尺寸；实测来源用到 4K 即可 |
| 重连 | Mac UU 客户端更新 | Mac UU 更新后需要检查日常桌面操作 | 更新后普通重连、直连中文输入和文本粘贴保持正常，4K 体验相近 |

[对比页](upstream-comparison.md)区分上游基础、新版本兼容、Plus 新增功能与 Plus 使用期间的修正。

![上游基础、Plus 变化与设计预期](../../images/uu-plus-evolution-zh-Hans.png)

[可编辑 SVG](../../images/uu-plus-evolution-zh-Hans.svg)

**设计预期：**文本及时刷新可减少重复粘贴；切换控制端时的焦点恢复仍需验证。较小画布每帧提供的像素更少；实际响应还受捕获、编码、网络和主控显示影响。

## 画布像素与选择

| 画布 | 每帧像素 | 相对 1080p |
| --- | ---: | ---: |
| 1280 × 720 | 921,600 | 0.44× |
| 1920 × 1080 | 2,073,600 | 1.00× |
| 2560 × 1440 | 3,686,400 | 1.78× |
| 3840 × 2160 | 8,294,400 | 4.00× |

这些是像素面积比。捕获可能处理完整源桌面，压缩、运动和网络影响实际负载。智能缩放放入完整桌面，不改变物理分辨率。

| 控制 | 用途 |
| --- | --- |
| Ubuntu 画布 | 中继图像大小；从 1080p 起步，精细文字／工作区可选 4K |
| 主控画质／FPS／真彩 | 压缩、请求更新速率、支持的色彩模式 |
| `uu-remote quality bitrate 20` | 20 Mbps 上限；`0` 取消。低上限可能损失运动细节 |

菜单、命令和恢复见[画质设置](quality-guide.md)。

## 源码构建成本

一次包含依赖准备和检查的完整冷源码构建得到：

| 项目 | 观察结果 |
| --- | --- |
| 耗时 | 699.851 秒，约 11 分 40 秒 |
| 资源限制 | 相当于双核的 CPU 配额；4 GiB 内存上限 |
| 报告峰值内存 | 约 1.8 GB，服务管理器舍入读数 |
| 报告交换使用 | 0 字节 |
| 输出 | 13 个 Windows 运行时二进制 |
| 可复现性 | 固定输入在不同源码／输出目录生成相同二进制字节 |

正常源码入口使用规范化路径和明确配置。新机器的下载与编译器可用性会影响耗时。已验证输出可以复用，见[源码构建](source-build.md)。

## 环境与同条件测量

| 环境 | Ubuntu | GNOME | Windows UU |
| --- | --- | --- | --- |
| 上游参考 | 24.04 | 46 | 4.33.0.8907 |
| Plus 本地观察 | 26.04 | 50 | 4.42.0.2770 |

现有记录没有固定上游与 Plus 同条件的控制端 FPS 或输入到可见屏幕延迟测量。中继计时与 CPU 配额实验属于组件测量。

固定主机／主控版本、源分辨率、应用、网络、UU 画质、请求帧率、码率。在独立临时环境运行固定上游和 Plus，考虑上游 24.04 安装边界。从定义输入动作开始计时，到主控可见响应；在可重复运动场景统计主控可见更新。重复运行，报告波动和文字清晰度，随结果保留测量方法。
